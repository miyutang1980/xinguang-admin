## 必須完成的 Gateway 部署

前台修正與 Apps Script 是兩個獨立部署。推送 GitHub 不會更新 Apps Script；尚未部署本函式前，舊 Gateway 仍會讀全表，前台只能篩掉歷史資料。

1. 開啟目前正式 Gateway 的 Apps Script 編輯器，先保留目前版本或複製程式碼備份。
2. 搜尋 `function _routesList(adminUser, adminPass)`。
3. 將這個函式整段替換成同目錄 `routesList.gs` 內容。不要保留兩份同名函式，也不要覆蓋整份 Gateway，以免蓋掉先前 W 欄姓名更新。
4. 儲存，選「部署 → 管理部署 → 編輯 → 新版本 → 部署」。更新既有正式部署，不要建立新的網址。
5. 後台按 `Ctrl + Shift + R`，登入後開啟接送排程，按「重新載入」。
6. 驗收：115-1 顯示 8/31 與 9/21，原有十列保留；回應含 `scoped:true`、`semester:"115-1"`、`readRows:10`（若期間已新增，筆數應相應增加）。再次讀取須反映最新資料；不要用新增正式資料來測試。

本函式仍先呼叫原本 `_verifyPickupUser`。它不使用歷史列表快取、不呼叫會整欄格式化的 `_ensureRoutesSheet`，只從當期命名範圍起點讀到最後一列。缺少範圍會停止，不會偷偷改讀全表或其他來源。

## 下學期切換

歷史排程保留原表，作為後台封存紀錄；本次沒有實體搬移。切換學期不是瀏覽器本機快照，也不會因日期自動清除資料。

- 先核對新學期日期與名冊，備份排程及接送學員。
- 新學期資料應追加在原表末端；為其第一列建立對應命名範圍，例如 `XG_PICKUP_115_2`，向下涵蓋餘下列。
- 在 Apps Script 指令碼屬性設定 `PICKUP_ACTIVE_TERM`，格式為 `{"id":"115-2","start":"YYYY-MM-DD","end":"YYYY-MM-DD"}`，填入確認的實際日期。
- 同步更新前台 `PICKUP_TERM` 和名冊模組的當學期設定後部署，重新登入驗收。前後台學期不同時會停止載入，避免混用。
- 不要排序或刪除原表歷史列。既有系統以 `row_index` 連結學員，搬動列會破壞關聯；如需實體搬移，應另做穩定排程 ID 遷移與明細對照。

## 測試與限制

`node tests/gateway/pickup-semester.cjs` 驗證只讀當期區塊、列號保留、缺少範圍與驗證失敗時停止、即時讀回及學期切換。`node tests/browser/run.mjs` 使用合成資料驗證前台，不代表真實帳號或正式 Gateway 部署已完成。

本次縮小的是排程列表的讀取範圍；登入驗證、員工與學生名冊、接送學員明細仍是各自的後端讀取。尚未取得正式登入環境的端到端速度，不承諾秒數。

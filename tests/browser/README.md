# 登入、導向與接送排程回歸測試

執行 `node tests/browser/run.mjs`，需安裝 Playwright 與 Chromium。全部網路請求由測試攔截，僅使用虛構帳號、學生與排程，不呼叫正式 Gateway 或写入正式資料。

## 2026-09-22 修正範圍

- 自動登入只啟動一次；登入按鈕連點共用同一請求。
- 重複初始化不再切回儀表板，登出後忽略舊登入回應。
- 學生主檔、當期與歷史指派的實際入口、資料欄位與切換。
- 開班資訊的延遲成功或失敗不能覆蓋接送或學生頁面。
- 帳號管理與延遲模組的舊渲染工作不能覆蓋新頁面。
- 接送新增日期五條路線、單一路線、重複日期阻擋與讀回確認。
- 讀取失敗停用新增，重試入口有效。
- 接送請求不使用前端 60 秒快取，也不自動重送不確定的寫入。
- 接送讀寫統一 Gateway「接送排程」，不再使用來源不一致的舊 n8n；15 秒記憶體快取依登入世代隔離，手動刷新、寫入前後（含結果不確定）均失效。
- 排程只顯示 115-1（2026-08-31～2027-01-20）；歷史列不進入表格、週次或姓名摘要查詢，跨期新增與複製被阻擋。
- 接送明細 HTTP 404、權限錯誤與格式錯誤顯示「人數尚未確認」，不得儲存。
- 明細載入失敗仍可關閉；重試保留儲存後回呼並重新取得候選名冊。
- 舊版僅姓名的明細顯示唯讀，不將缺少學生編號誤當空白勾選。
- 候選名冊讀取失敗不快取成零人；過期視窗回應不得改寫新視窗。
- 不確定的明細儲存不得直接重送；不支援的舊清空操作暫停。
- 桌面錯誤畫面與手機候選名單截圖。
- 接送候選名單依學生編號連結主檔英文名，顯示「中文（英文）」；驗證主檔排序不同、姓名特殊字元、英文名空白與跨校快取共用。
- 新 Gateway 模式直接使用「學期班級指派!W」合併姓名，不额外請求學生主檔。
- 國小依 115-1 在學名冊去重產生，排除國中、幼兒園、離校、歷史與舊自訂清單。
- 既有非當期學校值保留但不可新選；接送中文／英文搜尋不取消已選學生。
- 學期指派列表使用合併欄位顯示與搜尋；名冊快取失效後讀回新姓名。

此測試證明前端流程與受控回應的處理，不代表真實使用者權限、正式後端延遲或寫入已完成驗收。

## 2026-09-23 登入等待期限修正

- POST 轉 GET 保留呼叫者的取消訊號與快取設定；已有取消訊號的請求不套用全域重試。
- 驗證另設獨立期限，涵蓋連線與 JSON 回應解析；即使傳輸層忽略取消，也能結束等待。
- 主要驗證期限為 5 秒，備援期限為 10 秒；兩者皆無回應時提示尚未登入並允許重試，不以本地硬寫帳號代替雲端驗證。
- `login-regression.js` 保留主要請求懸置，使用真正的 5 秒期限確認轉入備援，測試端不再主動中止請求。另驗證無隱藏重試、雙來源卡住、遲到成功不得登入及取消失效時的獨立期限。
- 2026-09-23 受控測試主要驗證轉備援為 5010 毫秒；此數值不是正式帳號登入成功時間。

# 接送等待時間回歸

`pickup-latency.js` 使用被刻意暫停的合成請求，確認先顯示排程、名冊共用請求、學期頁名冊重用、明細並行讀取、20 秒來源明確的逾時提示，以及批次失敗不展開逐筆查詢。測試不代表正式 Apps Script 實測速度，且不寫入正式資料。

## 2026-09-23 接送明細名冊效率修正

`roster-efficiency.js` 驗證下列流程，全程攔截外部請求，正式資料寫入次數為零。

- 名冊取得 4 分鐘後開啟明細，不再請求名冊；快照原取得時間不被重設。
- 同一明細視窗新增學校、重新繪製，固定使用已取得的名冊。
- 名冊超過 5 分鐘後儲存，先重新核對；學生已離校或換校則不送出寫入。
- 本機名冊失效通知會阻擋舊視窗儲存。
- 名冊失敗但明細成功，短期重試保留明細；明細失敗時則保留仍有效的名冊。
- 桌面與 375px 手機畫面、控制項及錯誤保護均受測。

5 分鐘是記憶體快照有效期，不代表跨裝置即時同步。直接修改試算表或其他裝置更新後，可用「重新載入」立即取得新資料；這些測試不證明正式 Gateway 的首次讀取耗時。
